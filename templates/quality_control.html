{{ "1. Comment une règle est évaluée"|t }}

{{ "Une règle détecte une ANOMALIE. Chaque nœud est une condition ; si l'ensemble est vrai pour un client, ce client est compté comme non conforme."|t }}

{{ "Combinaison ET / OU"|t }}
  • {{ "• Le connecteur OU ouvre un nouveau groupe."|t }}
  • {{ "• Les nœuds d'un même groupe sont reliés par ET."|t }}
  • {{ "• Anomalie détectée si AU MOINS UN groupe est entièrement vrai."|t }}
  • {{ "• Le connecteur du 1er nœud est ignoré."|t }}
{{ "Exemple : pour obtenir (A ET B) OU (B ET C)"|t }}
1. A  (connecteur ignoré)
2. ET  B
3. OU  B  ← ouvre le 2e groupe
4. ET  C

{{ "L'imbrication A ET (B OU C) n'existe pas : il faut la développer en (A ET B) OU (A ET C)."|t }}

{{ "4. Pièges courants"|t }}

{{ "Majuscules et accents"|t }}
{{ "Les opérateurs « Contient » et « Contient le mot exact » ignorent la casse, mais PAS les accents : « Retraité » ne correspond pas à « RETRAITE ». Préférer une racine sans accent (RETRAIT)."|t }}
{{ "Égal à (=)"|t }}
{{ "Sensible à la casse. « risque eleve » ne correspond PAS à « Risque eleve ». Vérifier l'orthographe exacte utilisée dans les données."|t }}
{{ "Champs vides"|t }}
{{ "Une comparaison numérique (>, <) sur un champ vide ne se déclenche jamais. Pour cibler les champs non renseignés, utiliser « Est vide »."|t }}
{{ "Conditions contradictoires"|t }}
{{ "« Longueur < 8 » ET « Longueur > 15 » sur le même champ ne remontera jamais rien. Pour un format invalide dans les deux sens, relier les deux nœuds par OU."|t }}
